# v0.5 功能交付说明

按用户安排暂未运行测试、Godot解析检查或实机验证。以下描述代码实现与资源结构。

## 鼠标与移动

actor.gd使用鼠标世界坐标减角色世界坐标的单位向量决定攻击，不再选取目标。前摇每帧允许微调方向；进入有效判定后固定攻击方向。近战形状与箭矢支持任意角度，人物显示取最近八向。

移动为归一化WASD，攻击期间乘武器阶段系数。移动与攻击面向独立，后退/横移可继续瞄准。默认未出招时跟随移动方向，站立保留方向。

Q仅在idle状态切换；当前攻击数据为出招快照，背包换装不会重置攻击或改写已开始招式的伤害与方向。

## 八向动画约定

方向命名：e / se / s / sw / w / nw / n / ne，屏幕y向下。
动画命名：idle_e、walk_e、windup_e、attack_e、recovery_e、hit_e、death_e；其余方向类推。

每向帧数：待机2、行走6、前摇3、攻击4、后摇3、受击2、死亡1；每向21帧，共168帧。

所有战斗角色共享一份SpriteFrames，角色用色调和首领大小区分。图像是运行时用Image生成的64×64透明占位帧，包含八向头部、肢体摆动和出招动作；武器与攻击轨迹仍在actor.gd叠加绘制。

正式美术可做同名SpriteFrames资源，通过eight_way_visual.gd替换cached/build_frames入口。保留脚底与碰撞中心一致的对齐关系；攻击阶段按phase_remaining映射帧，避免显示动画与实际判定脱节。

## 背包与装备事务

GridInventory绑定CharacterState，inventory仅保存背包内物品，equipment保存穿戴物品；统计总携带重量时合计两处并按instance_id去重。

所有拾取、穿戴、拖放、卸下、整理、拆分和丢弃都由GridInventory处理。操作失败会恢复原数量、位置、旋转、装备与物品归属，不会吞装备。背包扩缩容时尝试保持当前位置并安置溢出物品，失败拒绝操作。整理采用面积优先的首个可用位置策略，不承诺最优装箱；锁定物品保持原位。

切换武器不会创建新实例。卸下物品仍计携带重量，只有丢弃才减轻重量。

界面为1090×610逻辑尺寸，按视口居中和缩放；基础背包8×6，示例支撑背包10×6。其余尺寸按可用面板区域缩放格子。完整不同设备适配仍需后续统一验证。

## 掉落与拾取

WorldLoot保存ItemInstance或金币，金钱无占格实例。Main维护随机掉落、拾取距离和遮挡检查。训练木偶不会产出。

金币3个身位自动收取；任务物品2个身位自动收集至quest_items字典，免格免重；其他物品1.5个身位。装备手动E；材料自动默认关；消耗品“只补已有堆叠”默认关，只在已有相同减重率堆叠可以完整容纳时自动拾取。当前没有消耗品使用动作或效果，模式先为其预留。

所有自动物品拾取要通过有效负担上限检查；金币与任务物品不增加负担。失败自动提示一次，手动可以重试。主动丢弃物品标记auto_disabled，避免自动吸回；要E手动拾回。

初始武器和装备样例、敌人掉落、可破坏物材料以及隐藏房间奖励都接入同一条拾取路径。

## 后续统一验证应覆盖的重点

鼠标各角度与八向边界；斜向速度；攻击中的移动与冻结判定方向；关背包后的输入；拖放、旋转、穿脱和回滚；背包扩缩容；重量与抗击退；堆叠、拾取遮挡、超重与锁定；金币/任务物品不占格；重置状态。

这是待验证清单，不是已执行的测试结果。
